## 4단계 적용 정책

- 자동 생성 시 숙소는 출발일을 제외한 각 날짜의 마지막 Item으로 둔다.
- 숙소 Item은 체크인 시각을 추정하지 않으며 짐 정리 시간으로 30분을 확보한다.
- 경기 후 마지막 숙소 Item은 취침을 위한 복귀로 본다.
- 사용자가 숙소를 경기 전이나 오후로 옮긴 경우에도 30분 체류시간을 적용한다.
  다만 현재는 저장 일정 Item 수정 API가 없어 자동 생성기에는 마지막 배치만 구현했다.
- 모든 서로 다른 장소 간 이동에는 실제 이동시간과 별도로 15분의 환승·대기
  여유를 확보한다. 응답에서는 `travelMinutesFromPrevious`와
  `transferBufferMinutes`를 구분한다.
- 경기장은 기존 `requiredArrivalMinutes=40`만 적용하며 별도 추가 완충시간을
  더하지 않는다.
- TourAPI 원문에서 입장·매표 마감시각을 안전하게 하나로 해석할 수 있을 때만
  일정 제약으로 사용한다. 정보가 없거나 불확실하면 추정하지 않고 프론트에서
  `시간 확인 필요`로 안내한다.

## 경로 최적화 v0.2 반영

- 필수 장소를 먼저 처리하고 날짜별 Anchor 연결비용으로 후보 순위를 계산한다.
- 도착일은 도착지·숙소, 경기일은 숙소·경기장, 출발일은 숙소·출발지를
  기준으로 장소의 날짜 적합도를 비교한다.
- Greedy Insertion으로 모든 삽입 위치를 시험하고, 영업시간과 Anchor 제한을
  만족하면서 추가 이동시간이 가장 작은 위치를 채택한다.
- 초기 경로 생성 후 2-opt로 이동시간이 감소하는 구간 뒤집기를 적용한다.
- 2-opt가 영업시간이나 Anchor 조건을 위반하면 기존 경로를 유지한다.
- 제외 사유는 `CLOSED_DAY`, `OUTSIDE_BUSINESS_HOURS`, `INSUFFICIENT_TIME`,
  `DUPLICATE_PLACE`를 구분한다.
- 알고리즘 버전은 `greedy-insertion-2opt-v0.2`다.

## 장소 선별 v0.3 반영

- 필수 장소, 일반 사용자 선택 장소, 자동 추천 장소 순서로 처리한다.
- 각 장소를 첫날부터 소비하지 않고 여행 전체 날짜와 모든 삽입 위치에 대입한다.
- 실행 가능한 후보만 날짜 Anchor 적합도, 추가 이동시간, 영업 종료 여유,
  Anchor 도착 여유의 결정적인 정렬 기준으로 비교한다.
- 휴무, 입장 마감, 영업시간, 경기·출발 Anchor 충돌, 일반 시간 부족을
  경로 시뮬레이션 단계에서 구분한다.
- 동일 입력은 장소 목록 순서와 관계없이 같은 결과를 반환한다.
- 알고리즘 버전은 `multi-day-selection-v0.3`이다.

인기도·개인 선호·팬 로그 점수와 자동 추천 장소 삽입은 아직 입력 데이터가
없어 적용하지 않았다. 현재 우선순위는 `필수 여부 → 날짜 Anchor 적합도 →
추가 이동시간 → 시간 제약`이다.
