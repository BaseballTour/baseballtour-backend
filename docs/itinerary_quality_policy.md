# 일정 품질 검증 정책

일정 생성 결과는 `qualitySummary`로 품질 상태를 함께 반환한다.

- `PASS`: 구조 오류와 안내할 위험이 없음
- `WARNING`: 일정은 사용할 수 있지만 식사 누락, 긴 공백, 불확실한 영업시간,
  추정 이동시간처럼 사용자 확인이 필요한 항목이 있음
- `FAIL`: 여행 기간 이탈, 일정 겹침, 필수 Anchor 누락, 경기장 도착 조건 위반
  같은 구조 오류가 있음

점수는 100점에서 WARNING당 4점, ERROR당 25점을 차감한다. 점수는 순위나
마케팅 표시가 아니라 회귀 테스트와 운영 모니터링을 위한 지표다.

## 식사 정책

- 아침 07:00~10:30, 점심 11:30~14:00, 저녁 17:30~20:30
- 해당 시간대에 60분 이상의 빈 시간이 있을 때 식당을 우선 배치한다.
- 아침은 신분류 중분류 `FD03`을 먼저 사용한다.
- 식사 후보가 부족하면 일정을 실패시키지 않고 `MEAL_MISSING` 경고를 반환한다.
- 같은 식사 시간대의 식당 연속 배치는 허용하지 않는다.

## 영업시간 정책

- `PARSED`: 요일별 영업시간과 휴무일을 일정 제약에 반영한다.
- `MISSING`, `UNPARSABLE`, `COMPLEX`: 영업 중이라고 단정하지 않는다.
- 사용자가 직접 선택한 장소는 배치할 수 있으며 원문과
  `BUSINESS_HOURS_UNVERIFIED` 경고를 반환한다.
- 자동 추천은 `PARSED` 장소를 우선하고, 후보가 부족할 때만 불확실한 장소를
  사용한다.
